# /api-sync [--write]

Detect drift between three things:
1. **Code:** the schema generated by drf-spectacular.
2. **Contract:** `docs/03-api-contract.md`, which the frontend builds against.
3. **Committed schema:** `schema.yaml` / `schema.json` in the repo root.

## Steps

1. **Generate.** Run `uv run python manage.py spectacular --file <scratchpad>/schema.yaml --validate`. If it fails, report the error (often a missing `@extend_schema`) and stop. If `uv.lock` doesn't exist yet, say issue #1 must land first and stop.
2. **Extract** from the generated schema (parse the YAML with a short Python snippet run via `uv run python`):
   - every `METHOD path`;
   - response status codes per operation;
   - the top-level properties of each 2xx response, resolving `$ref`s one level deep;
   - security per operation (auth required or not).
3. **Compare with the contract.** Parse the endpoint table and resource shapes in `docs/03-api-contract.md`. Report:
   - endpoints in code but not in the contract, and the reverse;
   - auth mismatches (e.g. public in the contract, authenticated in code);
   - shape mismatches (fields missing or extra, list not paginated, wrapped single objects such as `{"Blogs": {...}}`).
4. **Compare with the committed schema.** Diff the generated file against `schema.yaml`; summarise it as added/removed/changed operations only.
5. **Report** in ≤15 lines: `IN SYNC` or a list of drift items, each with the issue it belongs to if one exists (e.g. response shapes → #10, pagination → #11). Don't paste the full schema.

## With `--write`

After the report, regenerate the committed files:
- `uv run python manage.py spectacular --file schema.yaml`
- `uv run python manage.py spectacular --format openapi-json --file schema.json`

**Never edit `docs/03-api-contract.md` automatically.** If the code is right and the contract is outdated, propose the exact table/shape edits and apply them only after the user agrees.
